# 机器人

桌上那台小机器人的一页：它在不在、电量、网络、音量、屏幕，
还有**头往哪边看、抬头还是低头**（一张俯视图一张侧视图）。

| 件 | 是什么 |
|---|---|
| [`robot-data.js`](robot-data.js) | 数据层。**fetch 只出现在这个文件里** —— 换后端只改它 |
| [`robot.js`](robot.js) | 渲染层。零依赖，一行 fetch 都没有 |
| [`robot.css`](robot.css) | 样式 |
| [`demo.html`](demo.html) | 双击就能看。拖两根滑杆，指针跟着转 |

## ⚠ 这一块**只有前端**

后端要你自己接。这是本项目定下来的：

> 后端不是所有人进度都一样，所以这块只带走前端 —— 每个人对机器人的需求都不一样。

还有更实在的一条：原项目那份后端功能写得不好，与其拿出来耽误别人，不如不带。
所以这里给的是一张画得很清楚的脸，和一份**接口形状**；至于脸后面接什么，你自己定。

这不是偷懒，是诚实：机器人这东西差别太大了 —— 型号不同、固件不同、
有人走 MQTT 有人走 HTTP 有人干脆本地串口。硬塞一份我们的后端给你，
你多半得先把它拆了。

## 你要实现的三条

```js
// robot-data.js 里的 EP
GET  /api/robot     → {online, why, engine, volume, brightness, theme,
                       battery:{level,charging}, network:{type,ssid,signal},
                       head:{yaw,pitch}, keep_awake}
POST /api/robot     ← {volume} | {brightness} | {head:{yaw,pitch}} | {reboot:true}
                    → {ok, awake, why}
GET  /api/timeline  → {items:[{kind,content,date,time}]}   // 它身上发生过的事
GET  /api/shots     → {items:[{file,url,text,time,yaw,pitch}]}  // 它拍过的照片
```

`normalize()` 已经把「嵌套形状」和「扁平形状」都收成一种了 ——
真机 `get_device_status` 回的是 `{audio_speaker:{volume},screen:{brightness,theme}}`
那种嵌套，也认。

**取不到后端不会白屏**：界面会明说「还没接后端，下面是占位数据，形状是真的、数不是」。
★ 别把占位数据当真的画上去 —— 那是这个项目第一条铁律。

## 两张示意图（这块最值钱的部分）

头的角度是这一页唯一一个**有空间感**的数据，画出来比写两行数字好懂得多。
几何原样照设计稿，别乱改：

- **俯视**：圆心 (120,122)、R=100，指针角 ＝ `yaw − 90°`，扇形是水平视场 **66°**
- **侧视**：圆心 (56,118)，抬角 `el = pitch + 20`，指针 R=108，扇形 R=94 ± 垂直视场一半（**49.5°/2**）
- 灰点是「正面」（回正点），实线是它此刻朝哪儿

**水平线以下是物理盲区**（画成了虚线）。镜头光轴自带上仰角，俯仰压到底也只到水平线 ——
人蹲下、躺下、伏案，它是真找不到。**软件补不了，只能把它垫高。**
这句话建议留在界面上：不写的话，用的人会以为是自己的机器人坏了。

## 量程

```js
yaw   -85 ~ 85     pitch  -20 ~ 88     回正点 {yaw:-3, pitch:-8}
```

★ 换一台机器人，先改 `robot-data.js` 里的 `LIMITS` 和 `FOV`。

## 装在哪

安装时勾了它，书房那一格上会多一个机器人（`.sf-bot`）—— 它不是书，
所以没有「抽出来」那套手感：书是被抽出书架，它是被戳了一下，歪头再弹回来。
